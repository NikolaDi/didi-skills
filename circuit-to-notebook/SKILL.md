# 电路方案笔记导出

## 目标
收到一张电路图片或原理图 PDF 后，完成：
1. 识别并核对元件、引脚、网络、参考地、输入输出和控制关系。
2. 建立机器可读的规范电路 JSON，作为唯一连接真源。
3. 按专业原理图阅读规范重新布局并绘制 SVG，不机械复刻原图位置。
4. 生成面向方案学习、检索、参数调整和设计复用的三栏 HTML 笔记。
5. 生成中心电路图+四周知识说明的 SVG 知识地图。
6. 生成供后续大模型读取和修改的 Markdown 说明。

## 默认交付文件
每个方案目录内输出以下 5 个文件；导出根目录另维护一份汇总索引：
- `<方案名>-电路数据.json`
- `<方案名>-方案笔记.html`
- `<方案名>-原理图.svg`
- `<方案名>-知识地图.svg`
- `<方案名>-模型使用说明.md`

## 导出路径与归档
- 每次导出前都必须询问用户本次保存的根目录，等待回复后再创建目录或写入导出文件。不得使用默认路径、工作目录或上次路径代替本次询问。
- 提问示例：「本次笔记保存到哪个目录？请提供导出根目录的绝对路径，我会在其中按方案建子目录，并更新汇总索引。」
- 文件统一放入 `<导出根目录>/<方案目录名>/`，根目录的 `circuit-notebooks-index.md` 提供各方案笔记入口。
- 目录结构、同名处理、索引更新和交付链接规则见 `references/export-rules.md`，导出前必须读取。

## 文件命名
方案名前缀使用：
`主要功能或方案或应用场景：细分约束`
例如：
`带使能的高边电流采样：浮动参考与PNP电流输出`

标题可保留原文；用于目录名和文件名前缀时，按导出规则清理文件系统不允许的字符。

## 工作流程
### 0. 询问本次导出路径
先执行「导出路径与归档」规则，拿到本次根目录后再开始导出。目录不可用时说明原因并重新询问，不得静默改存其他位置。

### 1. 识图与边界确认
- 从图片/PDF中识别所有可见元件、参数、网络名、引脚号、极性和连接点。
- 区分系统 GND、浮动参考、隔离地等不同参考网络。
- 对看不清的阻值、型号、引脚或交叉点标记为 `unknown`，不得猜测为确定事实。
- 非必要测试点 TP 可从学习图隐藏，但必须保留在 JSON 原始数据中。

### 2. 建立规范 JSON
JSON 是连接关系的唯一真源，数据约定见 `references/data-schema.md`。至少包括：
- 元件：ref、type、value/model、pins、original_ref、visible_in_main
- 网络：id、name、role、members
- interfaces：input/output/control/power/reference/bidirectional
- assumptions：计算假设与成立条件
- unknowns：待确认项
- layout_groups：功能分组
- sources/provenance：数据来源与核对信息

禁止分别手工维护 SVG 与 JSON 的连接关系。

### 3. 功能分析
按信号与能量流分析：
- 输入/采样
- 偏置/基准
- 主处理或放大
- 反馈/补偿
- 电平转换/功率器件
- 输出转换/滤波
- 保护
- 供电/使能

明确：
- 电路解决什么问题
- 信号如何传递
- 反馈路径是什么
- 核心公式及成立条件
- 参数调整影响哪些指标
- 误差、工作范围、动态与器件限制

### 4. 原理图布局原则
详细规则见 `references/layout-rules.md`。

核心优先级：
`真实连接/引脚角色 > 主信号链与反馈易读 > 输入输出与保护边界 > 高低电位和方向 > 通路连续 > 紧凑美观`

### 5. 标准器件符号
使用 `references/symbol-library.md` 中的统一符号规范。
常用元件必须保持一致的几何、引脚角色和文字位置。

### 6. HTML 方案笔记
首页采用三栏：
- 左：按信号/输入输出顺序组织的功能模块、设计依据、检索入口
- 中：原理图；多个学习模块可共用同一张相对完整主图
- 右：当前模块的工作原理、设计依据、公式、参数调整、工程边界

附加视图：
- 完整推导
- 接口/网络/元件表
- 原标号映射
- 参数试算
- 基础知识回顾
- 苏格拉底式自测
- 方案复用说明

### 7. 知识地图 SVG
- 中心是主原理图
- 四周围绕关键知识点
- 公式靠近相关功能
- 不为了知识点数量拆碎电路

### 8. 最终检查
按 `assets/model-usage-template.md` 生成模型使用说明，再进行以下检查。

至少检查：
- JSON 网络成员与 SVG 图面一致
- 已知引脚全部落到正确网络
- 极性/脚号/角色一致
- 输入/输出/控制/供电/参考标识明确
- 保护器件位于正确接口区域
- 元件标注就近且不穿线
- 主图在实际 HTML 中可读
- 功能模块切换只改变高亮/说明时保持视图稳定
- 5 个文件均位于本次选定的方案目录，文件间相对链接有效
- 汇总索引已更新且笔记链接有效，回复包含笔记、索引和导出目录的绝对路径链接

## 拆图规则
不要因为“知识点不同”而拆图。
仅当两个功能块：
- 电气相关性低；
- 接口少且明确；
- 独立阅读不需要频繁来回查看；
才绘制为多个小原理图。
否则保持在同一张相对完整主图中。
