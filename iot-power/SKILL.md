# IoT Power

所有 IoT Power 交互都必须使用已安装的 `computer-use` skill 及其 Windows UI 自动化 API，操作前先读取该 skill。不得改用 PowerShell UI 自动化、仅凭图像点击或通过终端驱动 GUI。

本 skill 已使用 **合宙 IoT Power 2.2.0.4** 和 CC 系列设备验证。对于更高版本，必须重新发现相关控件后才能视为兼容。

## 适用范围

支持以下操作：

- 发现正在运行的 IoT Power 窗口和界面中可见的 CC 设备；
- 连接用户选择的设备；
- 报告连接状态；
- 读取单次标准化测量快照；
- 按用户要求且适合 UI 自动化的频率连续观察快照；
- 运行用户指定的时长后保存监控数据；
- 在用户要求时断开连接。

不得声称能够访问原始波形采样或 USB 协议。本工作流只读取桌面应用无障碍树中公开的数值。

## 安全边界

- 未获得用户对该动作的明确授权，不得点击 `PowerOnButton`、修改输出电压/电流限制，或以其他方式给用户电路上电或断电。连接测量设备不等于授权开启电源输出。
- 未在动作执行时获得确认，不得点击 `ClearData`，也不得选择会丢弃现有测量数据的选项。
- 重新连接时可能出现提示：`重新抓取会清除当前数据 是否快速保存当前“监控数据”窗口的数据？`。如果快速保存不会覆盖现有文件，优先选择保留数据的快速保存路径。选择 `否` 会丢弃当前数据，必须在点击前立即征得确认。
- 保存操作不得覆盖已有文件。出现同名文件、替换或覆盖提示时必须停止，并在执行覆盖前立即征得用户确认。
- 遇到覆盖文件提示、固件更新、权限请求或意外模态窗口时，必须先停止操作，说明具体影响，并遵循当前 Computer Use 的确认策略。
- 任务结束时不得自动关闭 IoT Power 或断开连接，应保持用户要求的状态。

## 目标选择

1. 使用 Computer Use 列出应用。
2. 选择显示名称恰好为 `IoT Power` 的应用。已知的进程标识符中可能包含 `IoT Power.exe`。
3. 只有在返回的 IoT Power 窗口恰好为一个时才能观察或操作。不得自行构造或猜测窗口句柄。
4. 允许窗口标题包含版本文本或 `[update failed]` 等附加内容；这些内容不能作为连接状态信号。
5. 如果存在多个 IoT Power 窗口，报告返回的窗口标题并停止，等待用户明确选择。

优先使用无障碍控件，不使用坐标。当前元素索引只是临时句柄：每次操作前都要重新观察，并通过 Automation ID 定位元素。每次操作后刷新状态并验证界面结果。

| 含义 | Automation ID | 预期角色 |

| 输出开关 | `PowerOnButton` | button |

| 清除测量数据 | `ClearData` | button |
| 瞬时电压值 | `VTextBlock` | text |
| 瞬时电压单位 | `VUnitTextBlock` | text |
| 瞬时电流值 | `ATextBlock` | text |
| 瞬时电流单位 | `AUnitTextBlock` | text |
| 瞬时功率值 | `APowerTextBlock` | text |
| 瞬时功率单位 | `APowerUnitTextBlock` | text |
| 平均电压值 | `VoltageATextBlock` | text |

如果缺少必需控件，重新抓取完整无障碍树。截图仅用于诊断布局或模态窗口；不得悄悄用固定坐标替代缺失的 Automation ID。

## 发现设备

读取 `PortComboBox` 下的可选项。设备标识符必须按界面原样保留，例如 `[CC-1A5FB3500]`。

- 如果没有设备，报告 IoT Power 当前未显示可连接设备。
- 如果只有一个设备且用户未指定其他设备，选择该设备。
- 如果有多个设备且无法推断用户的选择，列出设备并询问使用哪一个。

不得将窗口其他位置的旧数值视为设备当前已连接的证据。

## 连接

1. 观察当前无障碍树，识别 `PortComboBox`、其中选中的设备和 `ConnectButton`。
2. 如果 `PortComboBox` 已禁用且采样时长正在递增，报告设备已连接，不要再次点击切换按钮。
3. 否则，点击一次 `ConnectButton` 当前对应的元素索引，并立即刷新状态。
4. 按上述安全边界处理已有数据提示。
5. 使用多个信号验证连接状态：
   - `PortComboBox` 已禁用；
   - `PowerOnButton` 和断开计时器变为可用；
   - `TotalTimeTextBlock` 已重置或正在递增；
   - 界面中的测量字段开始更新。

不得因为子标签 `连接` 和 `断开` 同时存在就推断连接状态；部分无障碍树会同时公开这两个切换标签。

## 读取快照

不执行点击，获取一次最新的无障碍观察。分别提取数值及其当前单位，因为 IoT Power 可能动态切换单位。

同时返回标准化 SI 数值和界面原始字符串：

```json
{
  "app_version": "2.2.0.4",
  "device": "CC-...",
  "connected": true,
  "sample_time": "00:00:10",
  "voltage_v": 0.0055,
  "current_a": null,
  "power_w": null,
  "average_voltage_v": 0.0054,
  "average_current_a": null,
  "average_power_w": null,
  "total_energy_wh": 0.0,
  "max_current_a": 0.0000002,
  "usb_packet_loss": 0,
  "raw": {
    "voltage": "0.0055 V",
    "current": "--.---- μA",
    "power": "--.---- μW"
  }
}
```

解析规则：

- 将 `--.----`、空文本和非数字占位符视为不可用，返回 `null`，不能返回零。
- 将 `μ`、`µ` 和 ASCII `u` 统一视为微（micro）前缀。
- 按 SI 系数 `1e-9`、`1e-6`、`1e-3`、`1`、`1e3` 分别转换 `n`、`μ`/`µ`/`u`、`m`、无前缀和 `k`。
- 使用相同的前缀系数，将 `μWh`、`mWh`、`Wh` 等电量单位转换为瓦时。
- 遇到未知单位时拒绝解析，不得猜测。
- 保留足以表示界面数值的小数精度，不得虚构精度。
- 如果调用方需要真实时间，应另外报告观察时生成的当前时间戳，不得与 `sample_time` 混淆。

## 连续观察快照

UI 快照适合人类尺度的监测，不适合高频采集。

- 除非用户要求更低频率，否则默认每秒获取一次快照。
- 如果用户要求更高频率，应说明 Computer Use 和无障碍树无法保证波形采集级别的时序精度。
- 每次采样前重新观察，不得复用旧的无障碍树、元素索引或截图 ID。
- 达到用户要求的时长或样本数、用户中断或出现明确的设备/应用故障时停止。
- 如实报告单位变化、数值不可用、连接丢失和非零丢包，不得对其做平滑掩盖。

## 定时运行并保存

当用户要求「运行指定时间以后保存数据」时，将运行时长和保存目标视为必需输入：

1. 将用户给出的时长解析为大于零的秒数。时长含糊或无效时，开始前询问；不得自行猜测。
2. 保存路径未提供时，在开始计时前询问。保留用户指定的文件名和扩展名；不得擅自改变导出格式。
3. 确认设备已连接且 `TotalTimeTextBlock` 正在递增。若需要连接设备，完成连接验证后才开始计时。
4. 记录开始时的单调时钟时间和 `TotalTimeTextBlock`。以单调时钟经过时间作为到期依据，并用采样时长的增量交叉检查；不得把应用启动时间或此前累计的采样时间算入本次运行时长。
5. 运行期间按用户要求观察快照。用户未要求中间读数时，不必为了计时持续点击或高频抓取界面，但必须在到期前确认应用和设备仍可用。
6. 达到指定时长后先读取最终快照，再从最新无障碍树中查找明确用于保存或导出当前监控数据的控件。不得根据文本相似度选择用途不明的按钮，也不得使用旧元素索引或固定坐标。
7. 在保存对话框中填写用户指定路径并执行保存。出现格式选择、同名文件、覆盖提示或目标路径不可写时，停止操作并说明具体问题；不得改存到其他位置或自动覆盖。
8. 保存后使用只读文件系统检查确认目标文件存在且不是保存前遗留的旧文件。无法验证时，不得声称保存成功，应报告界面结果和验证失败原因。
9. 报告要求时长、实际经过时长、保存路径、最终读数和保存验证结果。除非用户另有要求，否则保持设备连接，不关闭 IoT Power。

到期时间允许受 UI 自动化调度影响出现少量延迟。如果用户要求严格的毫秒级定时或无界面高频采集，应说明本 skill 不适用。

## 断开连接

只有在用户要求断开，或断开已明确包含在获批工作流中时，才能执行断开操作。

1. 通过最新观察验证连接状态。
2. 找到 `ConnectButton` 当前对应的元素索引并点击一次。
3. 刷新状态，验证 `PortComboBox` 已启用且采样已停止。
4. 如果出现保存/丢弃提示，默认保留数据，并遵循与重新连接相同的确认规则。

## 故障处理

- 如果应用未运行，请求 Computer Use 运行时启动已安装的 IoT Power 应用，然后重新枚举窗口。
- 如果激活或抓取失败，丢弃旧索引和坐标，重新选择一次应用/窗口，并重试一次。
- 如果模态窗口可见但不在主无障碍树中，枚举返回的窗口并检查所属对话框，不得透过被遮挡的主窗口点击。
- 如果定时运行期间应用退出、设备断开或采样时长停止递增，停止计时，不保存不完整数据，并报告实际运行时长和故障状态。只有用户明确要求时才保存故障前数据。
- 如果保存对话框或明确的保存/导出控件无法发现，报告缺失的控件信息并停止；不得通过重新连接触发保存提示来代替正常保存流程。
- 如果桌面已锁定或用户停止 Computer Use，立即停止操作。
- 遇到不受支持的 IoT Power 版本或 Automation ID 变更时，报告缺失的 ID，并抓取新的无障碍树进行分析。不得把旧数值冒充实时读数。

## 最终回复

先说明设备是否已连接及用户要求的读数。明确区分 `null`/不可用测量与数值零。定时保存任务还要说明要求时长、实际经过时长、保存路径和文件验证结果。说明执行过的数据保留操作、单位转换、丢包情况，以及输出保持关闭等与安全相关的状态。
