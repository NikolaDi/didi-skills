# SVG 图例索引与检查方法

## 图例用途

用独立构造的典型电路检查通用布局规则是否可执行。每张图包含可追踪的器件、逻辑端子、导线和网络身份，而不仅是功能方框。图例不绑定实际产品、料号、封装脚号或性能指标；数字器件使用逻辑脚名，分立器件显示必要的端子身份。

图例路径与 [典型电路画法](circuit-patterns.md) 的 14 个条目一一对应。只查看与当前任务相关的图例；更新通用画法后，复查受影响的图例。

## 检查顺序

### 1. 先确定拓扑与预期节点

- 由 [生成脚本](../scripts/generate_examples.py) 记录器件端子、导线端点、网络标签及预期节点，再生成 SVG。
- 用逻辑端子名确定节点成员，不从图形左右位置推断端子身份。
- 明确哪些端子应相连、哪些网络应分离。串联器件两侧、独立通道和不同供电域属于重点。
- 对图例中的开放端口明确其逻辑用途；不能以未连接标志掩盖数据缺失。

### 2. 检查实际图形的几何连通

使用 [检查脚本](../scripts/validate_examples.py)，先查看入口参数及输出位置，再按脚本支持的方式运行。

- 核对导线端点与引脚锚点是否匹配，标签是否有有效的归属点。
- 核对分支结点、路径相交、重叠或近似未接的情况，确保视觉表达与预期节点一致。
- 允许同一网络分散画出并通过明确标签关联，但不得合并其它独立节点。
- 比较图形路径与预期节点，不能仅验证元数据内部自洽。
- 检查失败时定位到具体图、端子、路径或网络，修复后仅复查受影响范围及相关完整性。

这是自建图例的几何/连接模型检查，不是原生 EDA 的 ERC，不包含器件库、封装和制造语义。

### 运行方式

在本 skill 的根目录运行。生成器只使用 Python 标准库；文字占位检查另外使用 Pillow 和 Noto Sans CJK 字体。缺少文字检查依赖时，查看脚本给出的警告，不把跳过的检查记作通过。

```bash
python3 scripts/generate_examples.py --output /tmp/schematic-examples
python3 scripts/validate_examples.py /tmp/schematic-examples --report /tmp/schematic-checks.json
inkscape /tmp/schematic-examples/06-opamp-feedback.svg --export-type=png --export-filename=/tmp/opamp-review.png
```

先查看脚本的 `--help`。不指定 `--output` 时，生成器会更新本 skill 的 `assets/examples/`；只有确实在更新图例时才使用这个默认位置。Inkscape 仅用于实际渲染，也可换用能正确显示中文和 SVG 路径的渲染器。

检查器从 SVG 的实际电气路径和锚点重建连接，核对断接、误并、悬空端点和分支结点，并检查文字边界与文字互相遮挡。它不会自动证明二极管极性、符号画法、文字与导线间距或器件性能正确；这些仍按下节逐图查看。

### 3. 实际渲染并人工查看

- 将 SVG 实际渲染后查看；只阅读源代码不算完成图面检查。
- 全图：功能顺序、模块面积、标题层次、留白和完整性。
- 目标阅读尺寸：位号、参数、端子身份和网络标签是否可读。
- 局部：主基线、辅助支路、结点、输入极性、文字遮挡、导线脱离和错误穿越。
- 黑白：不依赖颜色仍能判断电路连接和通道身份。
- 让主通路有基线、辅助支路有层次，同职责器件对齐；不随机高低摆放、不为填满页面拉长线路、不堆叠装饰卡片。

### 4. 分别记录结果

| 检查 | 状态 | 证据要求 |
|---|---|---|
| SVG 生成与解析 | 通过/失败/未执行 | 实际运行结果及文件完整性 |
| 几何连通与预期节点 | 通过/失败/未执行 | 实际检查结果及涉及节点 |
| 人工图面查看 | 通过/失败/未执行 | 已查看的图和尺度，实际发现及修复 |
| 原生 ERC | 不适用 | 自建 SVG 不具备原生 EDA 网络与器件库语义 |
| 实际器件性能/PCB | 不适用 | 此处未建立实际器件工程及物理布局 |

脚本检查通过与人工检查通过分别成立，不互相替代。不要把本文件的检查要求写成已经完成的检查结果。
